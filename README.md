# 🎙️ Voice Messenger (WebRTC + WebSocket)

Полнофункциональный веб-мессенджер с личными сообщениями и прямыми голосовыми звонками высокой четкости (WebRTC P2P) между любыми пользователями.

---

## 🚀 Возможности

- **Личные сообщения (Direct Messages):**
  - Мгновенная доставка через Socket.io.
  - Сохранение истории переписки во время сессии.
  - Счётчик непрочитанных сообщений в реальном времени.

- **Голосовые звонки (P2P WebRTC):**
  - Прямой аудиопоток между браузерами с минимальной задержкой.
  - Автоматическая регулировка громкости (AGC), эхоподавление (Echo Cancellation) и шумоподавление.
  - Генерация звуковых сигналов (гудки вызова, мелодия входящего звонка, сигнал сброса) через Web Audio API (без внешних аудиофайлов).
  - Живой визуализатор голоса (Audio Visualizer) для микрофона и голоса собеседника.
  - Таймер продолжительности разговора.
  - Включение / выключение микрофона (Mute / Unmute).

- **Статусы пользователей:**
  - Автоматическое отслеживание «В сети» (Online) и «В звонке» (In Call).
  - Защита от параллельных звонков («Пользователь занят»).

---

## 🛠️ Стек технологий

- **Фронтенд:** React 19, TypeScript, Vite, Tailwind CSS v4, Lucide Icons.
- **Бэкенд:** Node.js, Express, Socket.io, TypeScript (`tsx`).
- **Связь и медиа:** WebRTC API (`RTCPeerConnection`), Web Audio API, Google STUN Servers.

## 📦 Быстрый старт

### 1. Запуск сервера и клиента одной командой:
```bash
npm run dev
```

Или по отдельности:
- **Сервер:** `npm run dev:server` (работает на `http://localhost:3001`)
- **Клиент:** `npm run dev:client` (работает на `http://localhost:5173`)

### 2. Как протестировать звонок и сообщения:
1. Откройте в браузере `http://localhost:5173`.
2. Введите первое имя (например, `Alice`) и войдите.
3. Откройте вторую вкладку браузера (или режим инкогнито) на `http://localhost:5173`.
4. Введите второе имя (например, `Bob`) и войдите.
5. Вы увидите пользователей в списке «Онлайн». Нажмите **«Позвонить»** или отправьте личное текстовое сообщение!

## 🏠 Хостинг в локальной сети (подключение друга) — v1.0.13

Если сервер запущен **на вашем ПК**, друг может подключиться напрямую по локальной сети.
Сервер теперь **гарантированно слушает все интерфейсы (`0.0.0.0`)** и при старте печатает
готовые ссылки вида `http://192.168.x.x:3001`.

### Пошагово:

1. **Запустите сервер** на своём ПК (`npm run dev` или настольное приложение).
   В консоли появятся LAN-адреса, например:
   ```
   🚀 Voice Messenger Server v1.0.13 запущен
      Локально:       http://localhost:3001
      Для друзей (LAN):
        → http://192.168.1.42:3001
   ```

2. **Разрешите порт 3001 в брандмауэре Windows** (самая частая причина «у друга ничего
   не работало»). Откройте PowerShell **от администратора** на ПК-хосте:
   ```powershell
   # Входящие подключения к порту 3001 (TCP — веб и Socket.io)
   netsh advfirewall firewall add rule name="VoiceMessenger 3001 TCP" dir=in action=allow protocol=TCP localport=3001
   # UDP на всякий случай (STUN/медиа)
   netsh advfirewall firewall add rule name="VoiceMessenger 3001 UDP" dir=in action=allow protocol=UDP localport=3001
   ```
   Либо: Параметры Windows → Брандмауэр → Разрешить работу с приложением через брандмауэр →
   отметить **Node.js** для «Частной» сети.

3. **Убедитесь, что оба устройства в одной сети** (один роутер / один Wi-Fi).
   Гостевые Wi-Fi и «изоляция клиентов» в роутере ломают подключение.

4. **Друг подключается любым из способов:**
   - 🌐 **Браузер:** открывает ссылку из консоли — `http://192.168.1.42:3001`
     (сервер сам раздаёт собранный клиент — ничего устанавливать не нужно);
   - 🖥️ **Настольное приложение:** нажимает бейдж **«Настроить сервер»** в левом
     сайдбаре → вводит `http://192.168.1.42:3001` → «Сохранить».

5. **Звонки между устройствами.** WebRTC сначала пробует прямое P2P-соединение
   (STUN). Если сеть/НАТ мешают — приложение **автоматически переключается на
   relay через ваш сервер** (звук идёт через Socket.io), поэтому звонок работает
   даже там, где чистый P2P не проходит.

### Если друг всё равно не подключается (чек-лист):
| Симптом | Причина | Решение |
|---|---|---|
| Браузер друга: «не удаётся получить доступ к сайту» | Брандмауэр Windows | Команды `netsh` из шага 2 |
| Сайт открывается, но «Сервер… не отвечает» | Друг ввёл адрес без порта | Полный адрес: `http://IP:3001` |
| Работает дома, не работает у друга | Разные сети / изоляция клиентов | Один роутер, отключить AP/client isolation |
| Открывается только с ПК-хоста | Антивирус блокирует Node.js | Добавить Node.js в исключения |
| Обмен сообщениями есть, звонок молчит | Микрофон не выдан | Разрешить микрофон в браузере (иконка в адресной строке) |

### Для друзей из интернета (не LAN):
Нужен проброс порта на роутере (3001 → ваш ПК) либо публичный хостинг (например,
Render — в репозитории есть `render.yaml`). Затем друг вводит ваш публичный адрес
через бейдж «Настроить сервер».
