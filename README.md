# 🎙️ Voice Messenger (WebRTC + WebSocket)

Полнофункциональный веб-мессенджер с личными сообщениями и прямыми голосовыми звонками высокой четкости (WebRTC P2P) между любыми пользователями.

---

## 📥 Скачать готовое приложение (Windows) — v1.0.22

Самый простой способ — скачать готовый `.exe` со страницы релизов:

1. Откройте **https://github.com/advancedjunke/Voice-messenger-for-Z.AI/releases/latest**
2. Скачайте один из файлов:
   - `VoiceMessenger-Setup-1.0.22.exe` — установщик (установка в один клик, ярлык на рабочем столе, порты брандмауэра настраиваются сами);
   - `VoiceMessenger-Portable-1.0.22.exe` — портативная версия без установки (один файл).
3. Запустите. Windows может показать предупреждение SmartScreen (приложение не подписано
   платным сертификатом) → нажмите **«Подробнее» → «Выполнить в любом случае»**.
4. Всё. Ни Node.js, ни Electron скачивать не нужно — всё уже внутри `.exe`.
   Приложение само найдёт сервер в локальной сети, а если его нет — этот ПК
   сам станет хостом, и все, кто запустит приложение после, подключатся к нему.

### 🗄 База Neon — подключение своей базы (v1.0.22)

> До v1.0.21 строка подключения к базе вшивалась прямо в .exe и раздавалась
> каждому скачавшему — это была утечка кредов. Теперь секретов в сборке **нет**:
> база настраивается на машине-хосте (UI настроек, `server/.env`, а для
> лаунчера — `launcher.env`, см. раздел «Лаунчер: файл launcher.env» ниже).

Подключите СВОЮ базу (аккаунты и история переписки будут сохраняться в неё):

1. Зарегистрируйтесь на **https://neon.tech** (free tier) и создайте проект.
2. Скопируйте **Connection string** вида `postgresql://user:pass@ep-xxx.neon.tech/neondb?sslmode=require`
   (в Neon: Dashboard → Connect → Connection string).
3. В мессенджере: **Настройки (шестерёнка) → База данных (Neon PostgreSQL)** → вставьте строку →
   **«Подключить и перезапустить»**. Приложение перезапустится, и статус сменится на «Neon подключён».
4. Готово: аккаунты и вся история переписки теперь хранятся в вашей базе (видно в консоли Neon).
   Отключить можно там же кнопкой «Отключить базу».

> База нужна только ПК-хосту. Даже если база «заснула» (free tier Neon) — сервер сам
> дождётся её пробуждения: сообщения за это время не теряются, а доезжают в базу из очереди.
> Если вы запускаете сервер батником (`start-server.bat`) — создайте файл `server/.env`
> со строкой `DATABASE_URL=…` и перезапустите сервер.

### 🛠 Если видите «Нет связи с сервером»

1. Нажмите **«Перезапустить сервер»** — приложение само попробует поднять сервер на этом ПК.
2. Не помогло? Закройте приложение и запустите снова (порт 3001 мог быть занят другим процессом).
3. Всё ещё не работает — пришлите разработчику логи:
   - `%APPDATA%\VoiceMessenger\main.log` — журнал приложения;
   - `%APPDATA%\VoiceMessenger\server.log` — журнал встроенного сервера.
4. Мессенджер работает и без интернета: хост-ПК поднимает сервер локально,
   друзья в той же Wi-Fi/LAN-сети подключаются автоматически (UDP-поиск).

## 🚀 Возможности

- **База данных Neon PostgreSQL (v1.0.21+):**
  - Креды базы **не вшиты в сборку** (раньше строка подключения раздавалась каждому .exe — утечка). База настраивается на машине-хосте: через настройки приложения, `server/.env` или `launcher.env`.
  - Очередь сообщений: если Neon «просыпается», отправленные в это время сообщения НЕ теряются — автоматически сохраняются в базу после подключения; история ждёт пробуждения базы до 10 секунд.
  - Умное подключение: SSL включается только для Neon/баз с `sslmode`; если база «просыпается» (free tier Neon) — сервер делает повторные попытки и сам переключается на базу, когда она ожила.
  - Аккаунты, созданные пока база была недоступна, автоматически переносятся в неё (ничего не теряется).
  - Без базы всё тоже работает: файловый режим (accounts.json на ПК хоста).

- **Исправлен запуск сервера в .exe (v1.0.18):**
  - Раньше встроенный сервер падал внутри приложения (electron-builder выбрасывал `server/node_modules`), и приложение молча переключалось на мёртвый облачный адрес → «Нет связи с сервером».
  - Теперь все зависимости сервера упакованы в один файл (`index.bundle.mjs`, esbuild) — сервер стартует всегда.
  - Кнопка «Перезапустить сервер» на экране входа реально перезапускает цепочку (localhost → UDP-поиск → встроенный хост).
  - Логи пишутся в файл: `%APPDATA%\VoiceMessenger\main.log` (и `server.log` для процесса сервера) — легко прислать разработчику при проблеме.

- **Аккаунты: регистрация и вход (v1.0.17):**
  - Явные вкладки «Вход» и «Регистрация» с паролем (мин. 4 символа).
  - Живая проверка занятости имени прямо при вводе.
  - Токен сессии — приложение помнит вход между запусками.
  - Аккаунты хранятся на сервере (Neon БД или файл `accounts.json` рядом с сервером) и переживают перезапуск.
  - Понятный статус сервера на экране входа: зелёный «на связи» / красный «нет связи» (раньше кнопка молчала).

- **Личные сообщения (Direct Messages):**
  - Мгновенная доставка через Socket.io.
  - Сохранение истории переписки во время сессии.
  - Счётчик непрочитанных сообщений в реальном времени.

- **Голосовые звонки (P2P WebRTC):**
  - Прямой аудиопоток между браузерами с минимальной задержкой.
  - Автоматическая регулировка громкости (AGC), эхоподавление (Echo Cancellation) и шумоподавление.
  - Генерация звуковых сигналов (гудки вызова, мелодия входящего звонка, сигнал сброса) через Web Audio API (без внешних аудиофайлов).
  - Живой визуализатор голоса (Audio Visualizer) для микрофона и голоса собеседника.
  - Таймер продолжительности разговора.
  - Включение / выключение микрофона (Mute / Unmute).

- **Статусы пользователей:**
  - Автоматическое отслеживание «В сети» (Online) и «В звонке» (In Call).
  - Защита от параллельных звонков («Пользователь занят»).

## 📦 Быстрый старт

### 1. Запуск сервера и клиента одной командой:
```bash
npm run dev
```

Или по отдельности:
- **Сервер:** `npm run dev:server` (работает на `http://localhost:3001`)
- **Клиент:** `npm run dev:client` (работает на `http://localhost:5173`)

### 2. Как протестировать звонок и сообщения:
1. Откройте в браузере `http://localhost:5173`.
2. Введите первое имя (например, `Alice`) и войдите.
3. Откройте вторую вкладку браузера (или режим инкогнито) на `http://localhost:5173`.
4. Введите второе имя (например, `Bob`) и войдите.
5. Вы увидите пользователей в списке «Онлайн». Нажмите **«Позвонить»** или отправьте личное текстовое сообщение!

## ⚡ Автозапуск и батники (v1.0.14–v1.0.15) — «никто ничего не настраивает»

Теперь работает **умная цепочка запуска**. Логика одна и та же и в настольном
приложении, и при открытии через браузер:

```
Кто-то запускает приложение
        │
        ▼
Шаг 1. Сервер уже работает на ЭТОМ ПК?  ── да ──►  подключаемся к нему
        │ нет
        ▼
Шаг 2. UDP-broadcast: есть ли сервер у кого-то   ── да ──►  подключаемся
        в локальной сети? (порт 3002, поиск          к найденному хосту
        занимает ~2 секунды)
        │ нет
        ▼
Шаг 3. Никого нет → ЭТОТ человек становится ХОСТОМ:
        приложение само поднимает встроенный сервер
        (Node.js уже внутри Electron — ставить ничего не нужно)
        │
        ▼
Все, кто запустит приложение после него, найдут этот сервер
через Шаг 2 и подключатся автоматически.
```

Итог: **первый, кто открыл приложение, автоматически становится сервером,
остальные просто открывают приложение — и попадают в общий чат.** Никаких
IP, команд и настроек.

### start-server.bat — выделенный сервер одной кнопкой

В корне проекта лежит `start-server.bat` (он же кладётся рядом с .exe при
сборке приложения). Нужен, когда хочется поднять сервер на отдельной машине,
которая всегда включена. Батник сам:

1. проверяет Node.js (подскажет ссылку на установку, если его нет);
2. ставит зависимости и собирает проект (только при первом запуске);
3. **добавляет правила брандмауэра Windows** (порты 3001 TCP/UDP + 3002 UDP) —
   если не хватило прав администратора, предложит запустить файл от админа;
4. запускает сервер и печатает ссылки для друзей (`http://192.168.x.x:3001`).

> Просто скопируйте папку проекта на компьютер-хост и двойным кликом
> запустите `start-server.bat`. Окно сворачивать можно, закрывать — нет.
>
> ⚠️ Батник предназначен для папки с **исходниками**. В установленном
> приложении сервер лежит внутри `app.asar` и системным `node` не читается —
> там встроенный сервер стартует сам (см. «Сборка: app.asar и встроенный сервер»).

### start-app.bat — запуск самого приложения (мессенджера) одной кнопкой

**Это тот файл, который нужен обычному человеку.** Двойной клик — и открывается
окно мессенджера. Батник сам:

1. проверяет Node.js (подскажет ссылку на установку, если его нет);
2. ставит зависимости — Electron ~100 МБ, только при первом запуске (3–5 минут);
3. собирает сервер и интерфейс, если сборки ещё нет;
4. открывает порты брандмауэра Windows;
5. запускает окно мессенджера (Electron) — дальше работает умная цепочка:
   найдёт чужой сервер в сети → подключится к нему; не найдёт → этот ПК
   сам станет хостом.

> Если Electron по какой-то причине не установился, батник сам запустит сервер
> и откроет мессенджер в браузере на `http://localhost:3001` — ничего не сломается.

**Итого:** скачал ZIP → распаковал → двойной клик по `start-app.bat`. Всё.
Друзья делают то же самое на своих ПК — все оказываются в одном чате.

### Порты, которые должны быть открыты (итог)

| Порт | Протокол | Зачем |
|------|----------|-------|
| 3001 | TCP | Веб-интерфейс + Socket.io (чат/сигналинг/relay-звук) |
| 3001 | UDP | Медиа WebRTC (P2P-аудио) |
| 3002 | UDP | Автопоиск сервера в сети (кто хост?) |

## 🏠 Хостинг в локальной сети (подключение друга)

Если сервер запущен **на вашем ПК**, друг может подключиться напрямую по локальной сети.
Сервер теперь **гарантированно слушает все интерфейсы (`0.0.0.0`)** и при старте печатает
готовые ссылки вида `http://192.168.x.x:3001`.

### Пошагово:

1. **Запустите сервер** на своём ПК (`npm run dev` или настольное приложение).
   В консоли появятся LAN-адреса, например:
   ```
   🚀 Voice Messenger Server v1.0.22 запущен
      Локально:       http://localhost:3001
      Для друзей (LAN):
        → http://192.168.1.42:3001
   ```

2. **Разрешите порт 3001 в брандмауэре Windows** (самая частая причина «у друга ничего
   не работало»). Откройте PowerShell **от администратора** на ПК-хосте:
   ```powershell
   # Входящие подключения к порту 3001 (TCP — веб и Socket.io)
   netsh advfirewall firewall add rule name="VoiceMessenger 3001 TCP" dir=in action=allow protocol=TCP localport=3001
   # UDP на всякий случай (STUN/медиа)
   netsh advfirewall firewall add rule name="VoiceMessenger 3001 UDP" dir=in action=allow protocol=UDP localport=3001
   ```
   Либо: Параметры Windows → Брандмауэр → Разрешить работу с приложением через брандмауэр →
   отметить **Node.js** для «Частной» сети.

3. **Убедитесь, что оба устройства в одной сети** (один роутер / один Wi-Fi).
   Гостевые Wi-Fi и «изоляция клиентов» в роутере ломают подключение.

4. **Друг подключается любым из способов:**
   - 🌐 **Браузер:** открывает ссылку из консоли — `http://192.168.1.42:3001`
     (сервер сам раздаёт собранный клиент — ничего устанавливать не нужно);
   - 🖥️ **Настольное приложение:** нажимает бейдж **«Настроить сервер»** в левом
     сайдбаре → вводит `http://192.168.1.42:3001` → «Сохранить».

5. **Звонки между устройствами.** WebRTC сначала пробует прямое P2P-соединение
   (STUN). Если сеть/НАТ мешают — приложение **автоматически переключается на
   relay через ваш сервер** (звук идёт через Socket.io), поэтому звонок работает
   даже там, где чистый P2P не проходит.

### Если друг всё равно не подключается (чек-лист):
| Симптом | Причина | Решение |
|---|---|---|
| Браузер друга: «не удаётся получить доступ к сайту» | Брандмауэр Windows | Команды `netsh` из шага 2 |
| Сайт открывается, но «Сервер… не отвечает» | Друг ввёл адрес без порта | Полный адрес: `http://IP:3001` |
| Работает дома, не работает у друга | Разные сети / изоляция клиентов | Один роутер, отключить AP/client isolation |
| Открывается только с ПК-хоста | Антивирус блокирует Node.js | Добавить Node.js в исключения |
| Обмен сообщениями есть, звонок молчит | Микрофон не выдан | Разрешить микрофон в браузере (иконка в адресной строке) |

### Для друзей из интернета (не LAN):
Нужен проброс порта на роутере (3001 → ваш ПК) либо публичный хостинг (например,
Render — в репозитории есть `render.yaml`). Затем друг вводит ваш публичный адрес
через бейдж «Настроить сервер».

## ⚙️ Эксплуатация (v1.0.22): лаунчер, обновления, TURN

Раздел для того, кто **разворачивает мессенджер у себя**: настраивает лаунчер
на машине-хосте, публикует обновления или собирает клиент со своим TURN.

### 🚀 Лаунчер: файл launcher.env

Начиная с v1.0.21 лаунчер (`VoiceLauncher.exe`) **не содержит секретов** — все
настройки, которые раньше были вшиты в exe, вынесены в файл `launcher.env`.
Формат: обычный текст в UTF-8, строки `KEY=VALUE` по одной на строку; пустые
строки и комментарии (начинаются с `#` или `;`) игнорируются.

**Где лаунчер ищет файл (по порядку):**

1. `launcher.env` **рядом с `VoiceLauncher.exe`**;
2. `%APPDATA%\VoiceMessenger\launcher.env` — фолбэк.

**Ключи:**

| Ключ | Назначение | Если ключа нет |
|------|------------|----------------|
| `NEON_URL` | HTTP SQL-прокси Neon — через него лаунчер проверяет таблицу релизов | Проверка БД полностью пропускается — автономный режим |
| `NEON_CONN` | строка подключения PostgreSQL (секрет!) | То же — автономный режим |
| `SERVER_UPDATE_URL` | базовый URL сервера обновлений (запасной источник пакета) | HTTP-источник пропускается; остаётся `download_url` из БД |

Пример:

```ini
# launcher.env — держите в тайне, НЕ кладите в git и в архивы для друзей
NEON_URL=https://ep-xxx-xxx.eu-central-1.aws.neon.tech/sqlserver
NEON_CONN=postgresql://user:pass@ep-xxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require
SERVER_UPDATE_URL=http://192.168.1.42:3001
```

**Безопасность.** Значения ключей — это креды, поэтому лаунчер пишет в
`launcher.log` только факт их наличия (`NEON_URL=ok`, `NEON_CONN=MISSING`),
сами значения в логи не попадают. Если `NEON_URL`/`NEON_CONN` не найдены
(файла нет, ключей нет, файл не читается) — лаунчер не падает: он переходит
в автономный режим и автоматически запускает локальную версию как есть.

### 📦 Публикация обновлений (на сервере-хосте)

Публикация релиза — привилегированная операция: пакет `app.asar` исполняется
на машинах всех пользователей. Поэтому с v1.0.21 она защищена админ-токеном:

1. На машине, где работает сервер обновлений, задайте переменную окружения
   `VM_ADMIN_TOKEN` (произвольный секрет):
   ```powershell
   # текущая сессия PowerShell:
   $env:VM_ADMIN_TOKEN = "ваш-секрет"
   # или постоянно (Windows):
   setx VM_ADMIN_TOKEN "ваш-секрет"
   # или для локальной разработки — строка в server/.env:
   #   VM_ADMIN_TOKEN=ваш-секрет
   ```
2. Публикация: `npm run publish-update` (скрипт `publish-release.cjs`). Он
   читает **тот же** токен из окружения или `server/.env` и отправляет его
   в заголовке `x-admin-token` на `POST /api/updates/publish`.
3. Вместе с пакетом публикуется его **SHA-256** (`payloadSha256`) — релиз
   регистрируется и в Neon (`app_releases.payload_sha256`), и на сервере
   обновлений. Без токена скрипт даже не начнёт публикацию.
4. Если на сервере `VM_ADMIN_TOKEN` **не задан** — эндпоинт публикации
   отключён: `POST /api/updates/publish` отвечает `503` «Публикация
   обновлений отключена…». С неверным токеном — `403`. Так старая дыра
   «кто угодно раздаёт код всем клиентам» закрыта.

### 🔒 Проверка целостности обновлений (SHA-256)

Каждый релиз публикуется вместе с SHA-256 пакета `app.asar`. При установке
обновления лаунчер:

1. берёт ожидаемый хеш из БД (`payload_sha256`) или из ответа
   `GET /api/updates/check` (поле `payloadSha256`);
2. скачивает пакет (из БД или по ссылке) во временный файл `app.asar.tmp`;
3. считает SHA-256 от фактически скачанных байт **до того, как тронуть
   старый `app.asar`**;
4. несовпадение → «Хеш не совпал, обновление отклонено»: временный файл
   удаляется, `app.asar` не трогается, приложение запускается на прежней
   версии. Подмена исключена.

> Релизы, опубликованные до введения хешей, ставятся с предупреждением в лог
> («обновление без хеша — проверка пропущена») — обратная совместимость.

### 🌐 TURN-сервер (опционально)

По умолчанию звонки за сложными NAT идут через публичные TURN-серверы
OpenRelay (вшиты в клиент). Можно задать **свой** TURN при сборке клиента —
переменными окружения (пример — в `client/.env.example`):

```ini
# client/.env
VITE_TURN_URL=turn:turn.example.com:3478,turns:turn.example.com:5349?transport=tcp
VITE_TURN_USERNAME=my-user
VITE_TURN_CREDENTIAL=my-password
```

- `VITE_TURN_URL` — один или несколько URL через запятую;
- переменные читаются **на этапе сборки** (`vite build`) — после сборки менять
  их бесполезно, нужна пересборка;
- если переменные не заданы или заданы не полностью — используется публичный
  OpenRelay, поведение по умолчанию не меняется.

### 🛠 Сборка: app.asar и встроенный сервер

- Всё приложение (electron + `client/dist` + `server/dist`) упаковывается в
  `resources/app.asar` (`asar: true` в корневом `package.json`). Именно этот
  файл заменяет лаунчер при обновлении — поэтому одно обновление обновляет и
  клиент, и сервер целиком.
- Встроенный сервер стартует в два приёма: сначала in-process импорт
  `server/dist/index.bundle.mjs` прямо из asar; если он не поднялся — тем же
  файлом запускается отдельный процесс (`ELECTRON_RUN_AS_NODE`).
- **Проверено на v1.0.22 (Electron 35):** дочерний процесс с
  `ELECTRON_RUN_AS_NODE` — это тот же `VoiceMessenger.exe` в режиме Node.js,
  и он **умеет читать файлы внутри `app.asar`** — поддержка asar встроена в
  бинарник Electron (отключается только явной переменной `ELECTRON_NO_ASAR`).
  Фолбэк-запуск сервера изнутри asar работает (проверено прогоном: бандл
  сервера из asar поднимается, отвечает на `/health` и раздаёт клиентские
  файлы) — распаковывать `server/dist` наружу (`asarUnpack`) не требуется.
- `start-server.bat` в **установленном** приложении сервер не найдёт: файлы
  лежат внутри `app.asar`, а системный `node` архив не читает. Батник — для
  папки с исходниками; в установленном приложении встроенный сервер стартует
  сам.
